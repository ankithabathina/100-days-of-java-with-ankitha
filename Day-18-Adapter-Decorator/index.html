🎯 Objective

Learn two important Structural Design Patterns used in Java:

📖 Introduction to Structural Design Patterns

Structural Design Patterns focus on organizing classes and objects to create larger, more flexible software structures.

They simplify relationships between objects, promote code reuse, and make applications easier to maintain.

Why use Structural Design Patterns?
  • Increase flexibility
  • Improve code reuse
  • Reduce coupling
  • Simplify integration
  • Make applications easier to maintain

Types of Structural Design Patterns

  • Adapter
  • Bridge
  • Composite
  • Decorator
  • Facade
  • Flyweight
  • Proxy

🔌 Adapter Pattern

Definition

The Adapter Pattern allows two incompatible interfaces to work together. It acts as a bridge between an existing class and the interface expected by the client.

Why Adapter Pattern?

Imagine your laptop only has a USB-C port, but your pendrive uses USB-A. Instead of replacing the pendrive, you use a USB adapter. Similarly, in Java, an Adapter converts one interface into another, allowing existing classes to work together without modification.

Real-Life Examples
  • USB to HDMI Adapter
  • Mobile Charger Adapter
  • Travel Plug Adapter
  • Memory Card Reader
  • Language Translator

Components of Adapter Pattern

  • Target – The interface expected by the client.
  • Adaptee – The existing class that has incompatible functionality.
  • Adapter – Converts the Adaptee interface into the Target interface.
  • Client – Uses the Target interface to communicate with the Adapter.

Adapter Pattern Workflow


Client
   │
   ▼
Target Interface
   │
   ▼
Adapter
   │
   ▼
Adaptee

The client communicates with the Target Interface. The Adapter translates the request and forwards it to the Adaptee, allowing incompatible classes to work together.

Advantages

  • Improves compatibility between different interfaces.
  • Promotes code reusability.
  • Reduces duplicate code.
  • Supports legacy system integration.
  • Encourages loose coupling.

Disadvantages

  • Adds an extra layer between classes.
  • Can increase the number of classes in the project.
  • May slightly increase application complexity.

Real-Time Applications

  • JDBC Drivers
  • Spring MVC Handler Adapter
  • Payment Gateway Integration
  • Third-party API Integration
  • Legacy System Integration
  • USB Device Adapters

Java Example Explanation

In our Java program, the MediaPlayer interface acts as the Target.

The Mp4Player class is the Adaptee, which can only play MP4 files.

The MediaAdapter converts calls from the MediaPlayer interface into calls that the Mp4Player understands.

Key Point:

The Adapter Pattern enables existing classes with incompatible interfaces to work together without modifying their source code.

🎨 Decorator Pattern

Definition

The Decorator Pattern is a Structural Design Pattern that allows you to add new functionality to an object dynamically without modifying its existing code.

Instead of changing the original class, the object is wrapped inside another object (Decorator) that provides additional behavior.

Why Decorator Pattern?

Suppose you order a Margherita Pizza. Instead of creating separate classes like:

  • CheesePizza
  • MushroomPizza
  • CheeseMushroomPizza
  • CheeseCornPizza

we simply decorate the original pizza by adding toppings one by one. This makes the application flexible and avoids creating too many classes.

Components of Decorator Pattern

  • Component – Defines the common interface.
  • Concrete Component – The original object.
  • Decorator – Wraps the component object.
  • Concrete Decorator – Adds additional functionality.

Decorator Pattern Workflow


Client
   │
   ▼
Decorator
   │
   ▼
Original Object

The client creates the original object and then wraps it with one or more decorators. Each decorator adds new functionality while preserving the original behavior.

Advantages

  • Adds functionality dynamically.
  • Follows the Open/Closed Principle.
  • Promotes composition over inheritance.
  • Easy to extend functionality.
  • Improves flexibility and maintainability.

Disadvantages

  • Can create many small classes.
  • May make debugging more difficult.
  • Object structure becomes more complex.

Real-Time Applications

  • Java I/O Streams
  • BufferedInputStream
  • BufferedReader
  • Spring Security Filters
  • Logging Frameworks
  • Notification Systems
  • Pizza and Coffee Customization

Java Example Explanation

In our Java program, Pizza is the Component interface.

MargheritaPizza is the Concrete Component.

PizzaDecorator wraps the Pizza object.

CheeseDecorator and MushroomDecorator add extra toppings without modifying the original Pizza class.

Key Point:

The Decorator Pattern lets us extend an object's functionality at runtime while keeping the original class unchanged.

⚖️ Adapter Pattern vs Decorator Pattern

Adapter Pattern Decorator Pattern
Converts one interface into another. Adds new functionality to an existing object.
Used to make incompatible classes work together. Used to enhance object behaviour dynamically.
Focuses on compatibility. Focuses on flexibility and extension.
Acts as a bridge between interfaces. Wraps an existing object.
Mostly used during integration. Mostly used for feature enhancement.

✅ Best Practices

  • Use Adapter Pattern when integrating incompatible interfaces.
  • Use Decorator Pattern to add new functionality without modifying existing classes.
  • Prefer composition over inheritance.
  • Keep each decorator focused on a single responsibility.
  • Avoid creating unnecessary decorators.
  • Follow the SOLID principles while designing applications.

📌 Conclusion

The Adapter Pattern enables incompatible interfaces to work together without changing existing code, making it ideal for integrating third-party libraries and legacy systems.

The Decorator Pattern allows developers to add new functionality dynamically by wrapping objects instead of modifying them, resulting in flexible and maintainable software.

Both patterns are widely used in enterprise Java applications, Spring Framework, and real-world software development.
