Objective

The objective of this project is to understand Java Lambda Expressions, their syntax, advantages, and real-world applications. Lambda Expressions simplify Java programming by reducing boilerplate code and supporting Functional Programming.

Introduction

Lambda Expressions were introduced in Java 8 to make Java code shorter, cleaner, and more readable. They allow developers to implement Functional Interfaces without creating Anonymous Inner Classes.

Lambda Expressions are widely used with the Collections Framework, Stream API, Comparator, Runnable, and Spring Boot applications.

What is a Lambda Expression?

A Lambda Expression is an anonymous function that contains parameters, an arrow operator (->), and a method body. 

(parameters) -> {

    // method body

}

Lambda Expressions make Java code concise and easier to understand.

Syntax of Lambda Expression

(parameter1, parameter2) -> {

    // statements

}

Example

() -> System.out.println("Hello Java");

(number) -> number * number;

(a, b) -> a + b;

Functional Interface

A Functional Interface is an interface that contains exactly one abstract method. Lambda Expressions can only be used with Functional Interfaces. 

@FunctionalInterface

interface Greeting{

    void message();

}

The @FunctionalInterface annotation tells the compiler that the interface should contain only one abstract method.

Lambda Expression Examples

Example 1 - No Parameters

Greeting greet = () ->

    System.out.println("Hello Java");

greet.message();

This Lambda Expression does not accept any parameters and simply prints a message.

Example 2 - One Parameter

Square square = (number) -> number * number;

System.out.println(square.findSquare(5));

This Lambda Expression accepts one parameter and returns its square.

Example 3 - Multiple Parameters

Addition add = (a,b) -> a + b;

System.out.println(add.add(10,20));

This Lambda Expression accepts two parameters and returns their sum.

Lambda with Collections

Lambda Expressions make working with Java Collections easier and more readable. 

List<String> names = new ArrayList<>();

names.add("Rahul");
names.add("Ankitha");
names.add("David");

names.forEach(name ->
    System.out.println(name));

Output

Rahul
Ankitha
David

The forEach() method iterates through every element in the collection and executes the Lambda Expression.

Sorting using Lambda Expression

Collections.sort(names,
(name1, name2) ->
name1.compareTo(name2));

Lambda Expressions simplify sorting by replacing anonymous inner classes with concise code.

Method Reference

A Method Reference is a shorter and cleaner way of writing Lambda Expressions when the Lambda simply calls an existing method.

Syntax

ClassName::methodName

Example

List names = Arrays.asList(
"Rahul",
"Ankitha",
"David"
);

names.forEach(System.out::println);

Here, System.out::println is a method reference that replaces the Lambda Expression: 

names.forEach(name -> System.out.println(name));

Lambda Expression vs Anonymous Class

Lambda Expression Anonymous Class
Less code More code
Easy to read Complex to read
Uses -> operator Uses class implementation
Introduced in Java 8 Available before Java 8
Supports Functional Programming Does not directly support Functional Programming

Advantages of Lambda Expressions

  • Reduces boilerplate code.
  • Improves code readability.
  • Supports Functional Programming.
  • Works seamlessly with Stream API.
  • Simplifies Collection operations.
  • Makes code easier to maintain.
  • Improves developer productivity.

Disadvantages of Lambda Expressions

  • Can be difficult for beginners.
  • Debugging complex Lambda Expressions can be challenging.
  • Works only with Functional Interfaces.
  • Overusing Lambda Expressions may reduce readability.

Real-Time Applications

Technology Usage
Collections Framework Sorting, Searching, Iteration
Stream API Filtering, Mapping, Reducing
Comparator Custom Sorting
Multithreading Runnable and ExecutorService
Spring Boot Functional Programming and Stream Processing

Best Practices

  • Keep Lambda Expressions short and simple.
  • Use meaningful parameter names.
  • Prefer Method References when appropriate.
  • Avoid deeply nested Lambda Expressions.
  • Use Lambda Expressions only with Functional Interfaces.
